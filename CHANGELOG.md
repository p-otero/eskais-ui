# Changelog

Versions follow [semver](https://semver.org). Before 1.0, a minor version can break compatibility. Release with `bun pm version <patch|minor|major>`, which bumps `package.json` and tags `vX.Y.Z`.

## Unreleased

### Added

- Density and corner radius are two theme axes. `data-density="default|compact"` (the `theme-compact` item) sets control heights and padding, every spacing role and the type steps; `data-radius="none|sm|md|lg|full"` (the `theme` item) sets `--radius`, `--control-radius`, `--choice-radius`, `--surface-radius` and `--floating-radius`, which without it still derive from `--radius` (`lg`). Both go on `<html>` or any element and nest; every component follows them through tokens. `data-theme="compact"` keeps working as an alias for compact density with the `md` radius and the flatter surface shadow, and a `data-density` or `data-radius` on the same element wins over it; `data-density="default"` restores the defaults inside a compact scope. sync-theme writes one rule per selector, and `node tooling/shell-check.mjs` renders all ten combinations at 1100px and 390px.
- `createAppearance({ density, radius, storage: { density, radius } })`: `appearance.density` and `appearance.radius` are preferences like `theme` and `palette`, and `<Appearance>` keeps `data-density` and `data-radius` on `<html>`; `"default"` leaves each off. `densities`, `radii` and the `Density` and `Radius` types are exported.
- The theme editor turns the glass theme on and off for the preview and the whole site, with a glass strength slider (0–100%, 40% by default) that sets `--glass-opacity` (100% minus the strength) and `--glass-blur` (half the strength in px) as a `[data-theme="glass"]` rule, never inline on `<html>`, so fills outside glass stay opaque and the no-`backdrop-filter` and reduced-transparency fallbacks still win. Both are kept with the other choices and written into the generated CSS; Reset turns glass off. Dialogs and drawers stay opaque under glass at any strength, which `node tooling/site-check.mjs` checks.
- The theme editor sets the density and the corner radius (the Radius slider is gone), keeps them on the docs site between visits, and writes a chosen step into the CSS as the attributes for `<html>`.
- `DocumentQuickOpenItem.snippet`: a passage of the note, like the one a server's search matched, shown as a second line under the label (`text-caption`, muted, cut at two lines) with every word of the query marked, case and accents folded as the command filter folds them (UI SDK's `matchRanges` and `matchSegments`). It is plain text, never markup. It works with `items` and with `source` (from `getItem`), and the rows stay on `CommandRows`, virtualized past 50. Agents and screen readers read an item as its label, folder and snippet, now separated by commas (`"Launch plan, Projects, The budget for…"`) where the folder used to run into the label.
- `CommandRows estimateItemSize(item)`: a command's height before it's measured, for rows taller than `h-control-sm`.
- `sortable`: reorder a list or grid by drag, keyboard and agents. A `definePrimitive` over UI SDK's `createReorder`, `createSelection` and `createRovingFocus`: `Sortable aria-label value onValueChange` (a `string[]`; reasons `drag`, `move-key`, `imperative`) renders `SortableItem`s from a children function of the order, which follows a separate draft while an item moves. Space or Enter lifts, the arrows, Home and End move, Space or Enter drops, Escape puts it back. Without `handle` it is a listbox of options; with `handle`, a list whose `SortableHandle`s are the one tab stop and the drag target, so an item's own buttons stay clickable. `selected` items move together (Ctrl/Cmd+Space or click), `disabledKeys` stay put, `preview` drags a copy and scrolls its list near the edges. Nothing re-renders while the pointer moves: core writes `--drag-x`/`--drag-y`, and items carry `data-grabbed`, `data-moving`, `data-checked` and `data-disabled`. Moves are announced and items described by keyboard instructions, all through overridable `labels`. Agents get `move(id, index)` and `reorder(ids)`; `agentMoves={false}` hides them. `useFlip` slides the neighbours with Web Animations timed by `duration-panel` and `ease-standard`, and does nothing under reduced motion.
- `Board` moves cards between columns: with `value` (a `Record<string, string[]>`) and `onValueChange(lists, { key, from, to, index })`, it wraps its columns in a `board-transfer` primitive over UI SDK's `createTransfer`. `BoardColumn value` renders its cards from a children function of their ids, as `BoardItem`s, and counts them; Left and Right change columns (`order`), `accepts(id, list)` skips a column that won't take a card, `handle` with `BoardItemHandle` keeps a card's buttons clickable (`handleFocus="card"` makes each handle a control of a card that is already one of the board's tab stops), a pointer drags a copy and scrolls near the edges. Agents get `move(id, list, index)`.
- `List sortable onReorder(ids, details)`: rows from data reorder by a drag handle named after each title (`sortableLabels`), the row's link or button keeps its own tab stop, checked rows move together, and agents get `move` and `reorder`. A sortable list renders every row instead of virtualizing.
- `AgentTaskBoard onMoveTask(move, details)`: cards get a drag handle and move between columns, which changes a task's status, and within one. The board reports `{ id, from, to, index, before }` and the host applies it; `moveTask(tasks, id, to, before)` does that and keeps the order under filters. To-do's Ready and Waiting groups each take only the tasks that fit them; by default proposals stay put and nothing moves into Proposed (`canMoveTask` overrides it). Agents get `moveTask(id, status, index?)` on an agent-only "Task moves" group that follows `agentApproval`, so a person confirms by default (`labels.moves.agentConfirm`); the board's own drag moves stay hidden from them. `labels.moves` in English and Spanish.
- `node tooling/sortable-check.mjs` (test:browser, test:compiler) drags in Chrome: a pointer move within a slot renders nothing, a drop commits, a copy held near a list's edge scrolls it, a card lands in another column, and nothing slides under reduced motion.
- `inline-edit` (definePrimitive on UI SDK's `createInlineEdit`): rename in place. The text is a button; a press (or a double click with `startOn="double-click"`), Enter, F2 or typing turns it into a field named by `label`. Enter and Tab save, Escape puts the text back without closing a surrounding dialog, focus returns to the text, and leaving the field saves (`blur="commit"`) or cancels (`blur="cancel"`). `validate` returning `false` keeps editing; `onValueChange` reports the reason through `createChange` and can cancel. An optional pencil button (`editButton`, `labels.edit`) shows on hover, focus and touch. Agents get `rename(text)` and `cancel`.
- `confirm-button` (definePrimitive): a button that asks twice. The first press arms it (`data-armed`, the destructive fill, its text and name become `labels.armed`, announced politely, in the same grid cell as the idle content so the width holds); the second runs `onConfirm`, pending with `aria-busy` while a returned Promise settles. It disarms after `timeout`, on Escape (only while armed) and when focus leaves, each reported through `onArmedChange` with `createChange` (`timeout`, `escape-key`, `focus-out`, `confirm`), which can cancel and be controlled with `armed`. `hold` also confirms on a held pointer, Enter or Space with a fill over `--confirm-hold-duration`, and swallows the click its release fires. `agentConfirm` becomes `data-agent-confirm`, so an agent's `confirm` waits for a person; the tests cover `allow` refusing and approving it.
- `image-cropper`: UI SDK `ImageCropper` styled. With no children it renders a viewport at the image's ratio (a square in `mode="frame"`), a selection with a background-coloured edge that dims the rest of the image with the `--overlay` colour, a grid at the thirds while dragging, eight handles that grow on touch (none in a frame), and a zoom slider with Rotate and Flip buttons that show an icon and a label from `labels`. `cropImage` is re-exported. In UI SDK 0.1.0-beta.5 axe reports the handles inside the selection's slider as nested-interactive; that test is marked as an expected failure and the showcase demo is a frame.

With no children it renders an area (painted on a canvas over a muted fill with `space="oklch"`), a hue slider, a swatch and a text field named by `labels.value`; the parts are rounded thumbs filled with the colour, a text field and channel inputs at the text-entry size, presets that grow to 44px on touch and an eye-dropper icon button with a tooltip that hides where the browser can't pick. The showcase's theme editor uses it, and `node tooling/touch-check.mjs` now measures its text field instead of skipping it.

It floats a `Field`'s label: with `labelPlacement="in"` the empty segments' placeholders stay hidden until one of them takes focus. `FormField` binds the ISO value, and `node tooling/touch-check.mjs` measures its segments.

A read-only rating's hidden radios inside its image are an axe nested-interactive in UI SDK 0.1.0-beta.5; the test is marked as an expected failure.
- `password-input`: UI SDK `PasswordInput` styled as the field's box, with the input and a reveal toggle inside: an icon button (an eye, a struck eye while shown) named "Show password" with the name in a tooltip, kept while `aria-pressed` says whether the password shows. With no children it renders both parts. Floats a `Field`'s label and binds through `FormField`; `node tooling/touch-check.mjs` now requires an autocomplete and a password input among the measured controls.
- `autocomplete`: UI SDK `Autocomplete` styled like `Combobox`: `AutocompleteControl` is the field's box around the input and its Clear and Trigger icon buttons (named "Clear" and "Show suggestions", with tooltips), the popup and items share the select list styles, and `AutocompleteItemText` marks the match in a heavier weight. The value is the text, so any text is valid. `useAsyncOptions` is re-exported for suggestions from a server. In a `Field` the label names the input and floats with `labelPlacement`, and `FormField` binds the text. A minimum query length for async suggestions comes with UI SDK 0.1.0-beta.10.
- `file-input`: UI SDK `FileInput` styled. `FileUpload title description browseLabel` is a dashed drop zone (primary while an acceptable drag is over it, the destructive soft tone for one it would refuse) with a browse button, the chosen files as `AttachmentThumb` chips with a remove button each (named and with a tooltip from `labels.remove`), and the files left out by `accept`, `maxSize`, `minSize`, `maxFiles` or `validate` listed under it with their reason (`labels.rejected`), which also marks the zone `data-invalid`. In a `Field`, the label names the browse button. The parts (`FileInputTrigger` with Button's variants, `FileInputDropzone`, `FileInputFiles`, `FileInputRejections`…) compose a button alone or a page-wide drop. Agents can clear it or remove a file; UI SDK 0.1.0-beta.10 stops agents from adding files.
- `tree`: UI SDK `Tree` styled as rows that indent by `--tree-level`, with a guide line down each open group through its parent's indicator, a chevron that turns (a spinner while `loadChildren` loads, a retry icon after a failure), tri-state checkboxes and an icon per node. `paths` or `items` with no children render every row (`treeFileIcon`: open or closed folders, file icons by extension; `icon` takes a function or `false`); `TreeNodes` renders the same rows from data inside a composed tree. `toggleTreeItem(items, checked, value, strategy)` computes a checked value from data. Items with `href` follow on press (`onFollow` routes them). For large trees, `visibleTreeRows` flattens the open branches for a virtualized list.
- `conversation`: `Conversation label composer` is a chat or agent thread on UI SDK's `createStickToBottom`: a named `role="log"` that follows the newest message while the reader is at the end (also while the last one grows as it streams), stops when they scroll up, and shows a pill that reads "Jump to latest" or "3 new below" (counting only messages that arrive below, not older ones loaded above) and jumps back, smoothly unless the reader prefers reduced motion, giving focus to the log. `ConversationMessage from author avatar time streaming actions` is an article named by its author and time, with `data-from` (`user`, `assistant`, `agent`, `system`, `tool`) and `aria-busy` while it streams; `ConversationComposer onSend` composes `Textarea` and `Button` (Enter sends, Shift+Enter starts a line, returning `false` keeps the text) and jumps to the newest message. `hasOlder` and `onLoadOlder` load older messages above without moving the view. It server renders, every label is overridable, and agents read the messages as items and call `jumpToLatest` and `loadOlder`. `node tooling/conversation-check.mjs` drives it in Chrome (test:browser, test:compiler).
- `activity-log`: `createActivityLog(agent, { within, keys, describe })` records who changed what and when: the page's UI SDK control changes from people, agents and the app's code, through UI SDK's experimental `createHistory` and `observe` kept behind its own types, plus the app's own changes through `log.record({ label, description, actor, undo, redo })`, in one timeline. `undo`, `redo`, `seek(n)` and `undoActor("agent")` restore through the agent bridge and resolve with what they couldn't put back. `ActivityLog log label` lists the entries newest first with the actor, the control's row and a relative time; pressing one seeks to it, Undo and Redo bind Cmd/Ctrl+Z and Shift+Cmd/Ctrl+Z outside text fields (listed in `ShortcutsDialog`), and agents call `undo`, `redo` and `seek` by position or by an entry's sentence, with `data-agent-confirm` on a seek back over more than `confirmAbove` entries. `undoToast(title, { log })` shows a toast with Undo.
- `Button shortcutWhen`: checked on every key press, so a shortcut can leave its keys to the page, like Cmd/Ctrl+Z to a focused text field.
- The showcase has an agent workspace (`?demo=agent-workspace`): a thread with a streaming agent beside an agent task board, and an activity log of the agent's moves and your changes, with undo toasts.
- `git-diff`, `text-diff`, `diff-view` and `diff` (lib): diffs for review. `TextDiff oldText newText language` compares two strings; `GitDiff patch` (or `files`) renders a multi-file git patch with a header per file (rename arrow, status chip, +/- counts and bar, mode change, collapse, Viewed checkbox that folds the file) and a tree of changed files (UI SDK Tree) to jump between them. Both are unified or split, number lines, fold unchanged regions behind Expand N lines, highlight changed words, wrap on demand and colour syntax with the Lezer parsers CodeBlock already loads, parsed in slices and applied only to the lines on screen. Every file's rows sit in one list under UI SDK's `createVirtualizer`, so a 20,000-line file or a 500-file patch opens in about 150 ms and scrolls without dropped frames on a desktop (`node tooling/diff-bench.mjs`; `bun run test:browser` runs it with `--ci`, which fails when a first paint passes 1.5 s, a key press or wheel scroll passes 100 ms at the 95th percentile, or more than 150 rows render). Unwrapped rows, file headers, gaps and notices take their heights from the theme and are never measured, line numbers are CSS on the line, and a parse that finishes re-renders only its own file's rows. The lines are a grid with one tab stop (`createGridFocus`): arrows, j/k between hunks, n/p between files, Enter to select a line and Shift to extend it (`onLineSelect` with GitHub's `side`/`line`), Escape to clear. Find in page reaches off-screen lines and opens a folded region or file it matches. Agents get `openFile`, `nextHunk`, `previousHunk`, `markViewed`, `getHunk` (read-only), `expandGap`, `setLayout` and `setWrap`. The engine (`diffText`, `diffFile`, `parsePatch`, `formatHunks`, `intraline`) has no dependencies: histogram (default) or linear-space Myers with a cost cut and git's slider placement, matching `git diff --histogram` and `--minimal` byte for byte on the fixtures; whitespace options; binary and size guards. `diffTextAsync` diffs in a Web Worker past 200k characters, built from the engine's source in a Blob so it works in every bundler, with a main-thread fallback.
- Diff sizing and headers: `TextDiff` and `DiffView` grow to the diff (`height="auto"`, the default) up to `--diff-max-height` (40rem) and scroll inside past it, instead of filling a fixed height and leaving it empty; `height="fill"` keeps a diff that fills a pane, and `GitDiff` fills by default. Binary files and mode-only changes show "Binary" or "Mode 100644 → 100755" (`labels.binaryFile`, `labels.modeChange`) in the header and the file tree instead of `+0 −0`, and a rename without changes shows no counts. A rename prints as git does, `docs/{old-name.md → new-name.md}`, and truncates only when the header runs out of room, with both paths whole in its tooltip and screen-reader name. The five-block stat bar takes one block per line below five changed lines, where it had filled every block; it stays decorative beside the visible counts, which screen readers hear in words.
- Diff colour tokens: `--diff-added`, `--diff-removed`, their `-strong` (changed words) and `-gutter` fills and `-foreground` (signs, counts), derived from the success and destructive tones. Every syntax colour keeps 4.5:1 on each fill in both modes and every palette; `bun run test:browser` checks them.
- `commit-history`: `CommitHistory` is a commit trail, one line per commit, on UI SDK's Tree. A lane runs down the side with a check on each commit; a merge is one row with a chevron, and opening it (a press, Enter, Right/Left, `expanded`) shows its merged branch's commits on a side lane that curves out of the merge and back at the fork point, drawn in as it opens. A press or Enter on any other commit opens its details under the row, animated by grid rows with the panel tokens: author and date in the page's language, the short hash with a copy button, files and +/- lines, the body. One at a time by default (`detailsMode`), and the other rows dim to `muted-foreground` meanwhile (`focusMode`). `status: "pending"` draws a spinning ring and `labels.pending` in the link colour in place of the time; when it lands the node grows into its check and the time and tags fade in. Messages turn backticked paths and git's merge subjects into the new `GitFileChip` and `GitBranchChip` (`git-chip`); `tags` are toned `Badge`s; times read "26m" and every row's name "Merge invoice-pdf into main, 38 minutes ago, Release". A `Select` switches `branches`. Rows virtualize with measured heights; 50,000 commits paint in about 70 ms and a held arrow key stays under 13 ms to paint at the 95th percentile (`node tooling/git-bench.mjs`). Agents get `expandDetails`, `collapseDetails`, `expand`, `collapse`, `copyHash` (returns the hash), `openCommit` (with `onOpenCommit`) and `selectBranch`, by a commit's id, hash or subject.
- `commit-graph` (lib): the model under it. `createCommitGraph` nests each merge's merged-in branch under it in one pass over `git log --topo-order` commits, `updateCommitGraph` carries a graph over when a page is appended or a commit only changes content (O(new rows)), `visibleRows` skips closed merges, and `createLaneLayout` lays out `git log --graph` lanes (stable lanes, merges, branch-outs, octopus merges up to `maxLanes`) lazily from the top, a row the first time it or one below it renders. `parseCommitMessage`, `commitSubject` and `createCommitFinder` read messages and find commits.
- `server-commit-history`: `ServerCommitHistory` pages a `CommitHistory` over a `PageSource` with `useServerInfinite`: older commits as the end scrolls into view and from Load more, the source's total in the header, the graph continuing across pages.
- `git-tree`: `GitTree` shows a repository's files at a commit on UI SDK's Tree (`treeFromPaths`): folders first with lucide icons, changed files marked added, modified, deleted or renamed by tone and a letter and named with their status, folders that hold a change marked and open. Typeahead, arrows and Left/Right from the Tree, `onOpenFile` and `current`; rows virtualize, so 100,000 files paint in about 140 ms. Agents `open`, `expand` and `collapse` by path.
- `CommitHistory view="branches"`: every active branch at a glance, a compact `git log --graph --all`. `branches` takes `{ name, head, tone?, ahead?, behind?, updatedAt?, author? }`; the base keeps lane 0, each unmerged branch runs in its own lane from its merge-base in a stable chart colour (or its `tone`), labelled at its head with a pill (name, ↑ahead ↓behind) that the row's name reads, and merged branches stay folded under their merge. The header select lists the active branches with a dot in their lane colour, arrows for ahead and behind (a zero side left out, spoken in words) and their last update, and filters them as you type; choosing one, pressing its pill or `focusBranch(name)` scrolls to its head and focuses it, and `filterBranch` shows only the base and that branch. Lanes past `maxLanes` collapse into "+N". Agents get `focusBranch` and the read-only `listBranches()`. `createBranchModel` (in `commit-graph`) works out ahead, behind, merge-base and state in O(commits + commits ahead); `createLaneLayout` now costs O(maxLanes + parents) a row however many lanes are open (an index of expected commits and a heap of free lanes), and takes `reserve`, `headTag` and `keepLanes`. Its rows report `hidden` lanes and per-lane `tagsTop`/`tagsBottom` in place of `overflow`.
- The commit trail matches the reference frames' density: 1.875rem rows (a touch target's height on a coarse pointer), caption times, borderless tag badges, and quieter `GitFileChip`/`GitBranchChip` (caption mono, leading-none, a translucent fill that shows on a highlighted row).
- `CommitHistory findable` and `GitTree findable`: find in page reaches the commits (by subject) and files (by name) scrolled out of view. Rows move to UI SDK's `createVirtualizer`, whose findable layers are built once the page is idle after its first paint, and a match scrolls its row into view and highlights it in the row. Off by default: `node tooling/git-bench.mjs` measures it at about a frame more on some held-arrow presses (p95 22–27 ms against 10 ms on 50,000 commits, about 16 ms against 10 ms on 100,000 files) and 10–40% more on the first paint; the layers are ready about 3 s after load. `GitFileChip` and `GitBranchChip` take `textRef` for it.
- `formatElapsed` (in `relative-time`'s `time` lib): how long ago in the locale's narrowest unit ("26m", "3h"), for a dense column.
- `CommandItem href`: a command that goes to a page renders as a link (an anchor that keeps the item's `data-slot`, styles and `option` role) and follows the repo's fast-link rules: Enter, a click, its `shortcut` or a primary mouse press follow it, a `#/…` hash route by setting `location.hash` and a same-origin path with `location.assign`, while other `#…` anchors and modified clicks stay native. A link command never runs `Command onAction`, which stays for actions. `onFollow(href, { event })` routes on the client (and closes the palette), `fast={false}` waits for the click, and `target`, `rel` and `download` reach the anchor. `useFastLink` takes `anchorRole` for an anchor root with a role other than link. The docs site's search uses link commands, so a page opens in a new tab on Ctrl/Cmd+click.
- `shell`: `searchQuery`, `defaultSearchQuery` and `onSearchQueryChange` control the palette's search; `ShellSearch` takes them as `query`, `defaultQuery` and `onQueryChange`. Without them, every open of the palette starts empty.
- `shell`: `sidebarShortcut` (off by default), like `"mod+b"`, toggles the sidebar on wide screens and opens its drawer on narrow ones. It is the topbar trigger's `shortcut`, so the trigger carries `aria-keyshortcuts`, shows the keys in its tooltip and `ShortcutsDialog` lists it.
- `shell`: the sidebar's state is reachable. Pass your own `useSidebarState()` result as `sidebar` to read or toggle it outside the Shell, or call `useShellSidebar()` inside it (pages, `actions`, `brand`) for `collapsed`, `setCollapsed` and the `controller`.

- `MasterDetail idleDetail="visible"`: on a container under 42rem, the detail stays under the list while nothing is open instead of hiding, for a live pane like a monitor. It sits at its content's height up to `--master-detail-idle-height` (50%), scrolls by keyboard, and its bar has a Collapse/Expand button (`labels.collapse`/`expand`, with a tooltip and `aria-expanded`) that folds it to the bar and keeps focus; with `collapsible` the idle detail gets the same button beside the list and folds to the rail. `emptyDetailTitle` titles the bar and names the pane. - `url-router` (lib): `UrlRouter`, `{ read, navigate, href, subscribe }` over the app's location as `{ path, params }`, for blocks that keep state in the URL. `hashRouter()` changes a hash route's query without touching its path (`#/devices?device=a1`) and builds `#/path?query` hrefs; `historyRouter()` does it for the path and query string; `memoryRouter()` is for tests; `withParam` sets one param. Both browser routers keep `history.state` and notify each other. `createUrlParam(name, { router })` and `routerUrlState(router)` (`url-state`) go through one, so an app wraps its own router's API instead of letting a block write URLs the router rewrites. `UrlParamAdapter` gains an optional `href(value)`. Defaults are unchanged. A new guide, Routing and the URL, covers the adapters and controlled selection for routes of the app's own shape (`#/devices/<id>`).
- `SettingsPage` section links take their href from the `url` adapter's new `href`, so `createUrlParam("section", { router: hashRouter() })` links to `#/settings?section=id` and a new tab opens the route, not a bare `#id` that replaces it; without `url` they stay `#id` anchors, and `getHref` still overrides. `navigation="buttons"` renders scroll-only buttons (`aria-current="location"`, pressed by agents by name) for sections with no address.

Its `aria-label` sat on a `div role="group"` around an unnamed `ul`, so `getByRole("list", { name })` found nothing and screen readers announced a group and then an unnamed list. The root is now the `ul` (`role="list"`, which Safari needs under Preflight) or, for a selectable list, the Listbox itself, each named by `aria-label`; the group is gone. Agents still find the list by that name with `select(id)`; a selectable list's listbox now shows beside it under the same name with `setValue`, and a step resolves by its action.
- `ChartDataTable` takes rows typed by an `interface`. It required `Record<string, unknown>` rows, so `interface Point { d: string; v: number }` failed with TS2322 (index signature missing). It is generic over `TRow extends object`, with `labelKey` and `keys` checked as `keyof TRow`. `ChartRow` is now `object`.
- `SidePanel` wraps its header actions below the title, as `CardHeader` does: the heading grows from `--card-heading-basis` (11rem), so a `StatusPill` and a small `Button` in a 24rem panel no longer squeeze the title and wrap the description one word per line. The close button keeps its corner. New slots: `side-panel-heading`, `side-panel-description`, `side-panel-actions`. `node tooling/shell-check.mjs` measures it at 24rem (`?demo=side-panel-check`).
- `SidePanel narrow` decides what happens on narrow screens. It always became `absolute inset-0`, hiding the page behind a panel open on load. `"stack"`, the new default, keeps it in the flow, full width, and wraps its flex parent so it goes below the list; it hides nothing and traps no focus. `"overlay"` is the old behaviour (the `inbox` block keeps it, its list being a tall scroller). `"sheet"` opens it as a modal bottom `Drawer`: focus moves in, its shortcuts still run, and Escape or the close button return focus to `returnFocus()`, resolved as it starts closing so a caller that clears its selection in `onOpenChange` still gets it. `use-media-query` (`useMediaQuery`, `narrowQuery`) joins the item. `node tooling/shell-check.mjs` checks each mode at 375px.
- Table cells no longer always truncate. `TableCell wrap` wraps long text onto more lines instead of cutting it at `max-w-80`, and `DataTableColumn` takes `wrap`, `cellClassName` and `headerClassName`. A cell that stays truncated now shows its whole text in a `title` while it overflows, set as the pointer arrives so cells that fit get none (a `title` you pass stays). `node tooling/shell-check.mjs` checks a wrapped column beside a truncated one (`?demo=table-check`).
- `lucide-react` is pinned to 1.68.0 (2026-11-04), the oldest release that exports every icon the registry uses, instead of 1.73.0 (2026-11-14): `shadcn add` failed with `ERR_PNPM_NO_MATURE_MATCHING_VERSION` for consumers with a 7-day pnpm `minimumReleaseAge`, since shadcn installs dependencies before it writes any file.
- Fast links work in hash routers: `@fast-link/core` 0.0.2 leaves every `#…` href native, so `Link`, `ButtonLink`, `NavigationMenuLink` and `FastLinkRegion` links to `#/route` only followed on release. An `href` that starts with `#/` now follows on press, through `onFollow` or by setting `location.hash`; other `#…` hrefs are in-page anchors and stay native. `data-fast-link-hash-prefix` on any ancestor, or `FastLinkRegion hashPrefix`, sets another prefix (`#!/`), and an empty one turns hash routes off.
- A `Field` inside a `Form` with `labelPlacement="in"` or `"on"` takes the Form's placement only in the floating layout: a `FieldLabel`, then a control that can float its label, then only a `FieldDescription` or `FieldError`, with no padding of its own. A Field styled as its own box (`className="border p-3"`, a help `<p>` after the control) drew its label over the control's value; it now keeps the label on top. A `FormField` with padding in its `className` does the same. A Field's or FormField's own `labelPlacement` still wins, `top` included.
- Item docs: `sidebar` said a `SidebarTrigger` renders nothing on narrow screens; it opens the Sidebar's drawer, and a Sidebar with `trigger={false}` renders no drawer button of its own. `virtual-rows` named `VirtualFindStubs`, which is `GapFindStubs`. A test fails when an item's docs or the skill name a component or hook that no registry file exports, or one marked deprecated.

### Fixed
