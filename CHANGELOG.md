# Changelog

Versions follow [semver](https://semver.org). Before 1.0, a minor version can break compatibility. Release with `bun pm version <patch|minor|major>`, which bumps `package.json`, rebuilds `public/r` (the mockup CLI reports the version) and tags `vX.Y.Z`.

## Unreleased

### Added

- `narrow`: `isRecord`, `isOneOf`, `isStringArray` and `isElementOf` (an `instanceof` by constructor name that also takes an element from another window, such as an iframe's) narrow values at runtime, and `keysOf`, `recordOf` and `assumeType` are the few casts the registry needs, each documented. `utils` adds `cssVars({ "--x": 1 })`, CSS custom properties typed for a `style` prop without a cast. `filter-schema` exports `isNumberOp`, `isNumberFilter`, `isDateInput` and `isDateRange`, and `code-highlight` exports `syntaxToneOf`.
- `server-data`: `patch` and `patchSource` resolve with what they did, as query keys in the cache's order: `{ written, cancelled, restarted, refetched }`. `written` are the queries the patch wrote; `cancelled` those whose read in flight it stopped (`inFlight: "cancel"`); `restarted` those whose read it started again (a written query's under `"restart"`, a first read it left empty under either, every read in flight under the key with `refetch`); `refetched` those the `refetch` reload read that weren't reading (a shown cancelled query is in both). A screen can now clear an error banner only when a read ran again, instead of checking `isFetching` before patching. A caller that ignores or awaits the result works as before; one that types the promise as `Promise<void>` widens it to `Promise<unknown>`.
- `server-data`: `useHoldSource(source)` and `holdSource(client, source)`, for a screen that fetches the answer itself (another request than the query's on a first load) and then writes it. A hold cancels every read in flight under the key at once and pauses the hooks' reads under it until it ends: they show as fetching and send nothing, and one the hold cancelled waits as one, so a first load stays pending and fetching. Reads a mount, focus or reconnect refetch, `retry` or an invalidation starts during the hold wait too, deduplicated. `hold.patch(changes, { refetch, awaitRestarted, throwOnError })` writes the answer with `inFlight: "cancel"` and ends the hold: a written query's paused read is dropped without a request, every other one runs and is listed in `restarted`. `hold.release()` ends it without writing, after the caller's fetch failed: every paused read runs once and nothing stays pending. Holds nest and overlap (a read waits for every hold over its key), the hook releases its component's holds on unmount, a read the hooks don't own (`prefetchQuery`) is cancelled and started again at the end, and a `patch` after the end still writes. No request is added: tests count every query function call across a reload, a first load given its value by the caller, a failed fetch and `release`, focus and `retry` during the hold, a mount, an invalidation, `refetch`, nested and overlapping holds, unmount, pages and infinite lists, a prefetch, and typed results and errors. It is a handle rather than a `patch(…, { firstLoad: fetcher })` option because the cancel has to happen before the caller's request, the answer decides what to write, and the caller may not write at all.

### Changed

- Registry code passes oxlint's type-aware `typescript/no-unsafe-type-assertion`, so a consumer who turns it on can lint the files they install: `bun run lint` runs it as an error on `registry/**` beside `restrict-template-expressions`, and CI runs `bun run lint`. The 309 narrowing assertions of 0.2.9 (129 in 0.2.8) are now runtime checks (type guards, `instanceof`, `in`, `Array.isArray`, typed lookups), generics or `satisfies`, `x[i]!` for an index already known to be in range, parsers where values come in from outside (filter URLs, a log viewer's JSON key, thrown form errors), and 57 `assumeType` calls where TypeScript can't follow the type: the server's JSON at a page source's boundary, TanStack Query's `unknown` cache, the invariance of react-hook-form's form and the page controller, `memo` dropping a component's type parameters, UI SDK part types, React Three Fiber's camera and CodeMirror's Markdown parser. Each call has its reason in a comment above it. `test/unsafe-casts.test.ts` holds that count, fails on an unexplained call, and allows `any` and disables of the rule only in `lib/narrow`, so a cast can't hide there. The `lint-rules` item has no type-aware rules; the installation guide and the skill recommend turning both on in a type-aware config. Items that now use `lib/narrow` depend on the new `narrow` item. No public type changed.
- On values outside their declared types, which typed callers can't pass, a few components now skip instead of using them: an `ImageScan` image part that isn't an `<img>` gets no load listener, a native select or inline edit bound to another element ignores its events, a filter value of the wrong shape is left out of the URL, chips and the request, thrown form errors that aren't a message or `{ code }` are dropped, and an array source sorts object values by their string form.
- `server-data`: `awaitRestarted` waits for exactly the reads in the result's `restarted`, so with `refetch` it also waits for a read in flight of a query the patch didn't write, which the reload restarted.

### Fixed

- `filter-rsql` and the other serializers: a filter negated three times, `not(not(not(x)))` with `x` an `and` or `or`, was written as if `x` were one condition; it now pushes the negation into `x`, as it does for one negation.

## 0.2.9 (2026-11-21)

### Added

- `eskais-mockup-cli`: `build --state <name>` renders the screen with a named state's props, from `export const states = { empty: { … }, loading: { … }, error: { … } }` in `fixtures.ts`, into `out-<state>-<theme>.html`; `--state all` builds one page per state (`--out` takes `{state}`), and `validate --state` server-renders them and lists them (`states 3: empty, loading, error`). Without `--state`, `build` and `validate` work as before.
- `eskais-mockup-cli`: `--tailwind <dir>` names a folder whose packages resolve Tailwind, and `--tsconfig <file>` the tsconfig for the aliases and the type check.
- `list-item`: `List rowActions={(id) => ListRowAction[]}` gives rows actions (Open URL, Copy, Start/Stop) that run without choosing the row, also in a selectable list and in a `MasterDetail`. The list becomes an APG layout grid, still one tab stop: a row is its primary cell (its link or button) and one cell per action; Up/Down and j/k keep the column, Left/Right move within the row, Home/End and Ctrl/⌘+Home/End reach a row's or the grid's ends. Selectable, rows carry `aria-selected` and only the primary column selects; a press, Enter or Space on an action never does. An action is `{ id, label, icon, onAction(details), href, newTab, disabled, confirm, tone }`: `details.cancel()` refuses it, `disabled` (true or why) keeps it focusable with the reason in its tooltip, `confirm` is its `data-agent-confirm`. Actions show on hover, focus or selection on a fine pointer (`rowActionsVisibility="always"` keeps them) and always on touch, with 44px hit areas. Agents get one component per action, named by its label, whose `run(id)` takes a row's id, rendered or not, and fails with why on a row that doesn't offer it, a disabled one or a cancelled run; the rows' own buttons stay out of the snapshot. `ListGroup` is a `rowgroup` there. The Row actions guide and `?demo=list-row-actions` show worktree environments with a status dot, their URL and Open, Copy and Start/Stop.
- `log-viewer`: `LogViewer` and `createLogStore`, a live log or terminal output viewer for any process, like a local environment's frontend, backend and database. The store takes whole lines (`append`) or a process's raw chunks (`write`, which holds a partial line until its newline and carries colours across lines per source) into a bounded buffer (`maxLines`, 10,000 by default) and notifies once per frame, or every few frames while rendering takes longer than half a frame. The viewer renders only the lines in view, on UI SDK's virtualizer inside a `ScrollArea`; follows the end until the reader scrolls up, then shows Jump to end with a count of new lines (End or the button follows again); filters by source (a `ToggleGroup`, each source marked with a chart or tone colour) and by search, with matches marked; marks error lines (an `error` or `fatal` level, or an `isError` pattern) and steps through them with F8 and Shift+F8 or the toolbar; copies the shown lines, or the selection, as plain text; wraps on demand; shows timestamps. The log is a named `role="log"` with `aria-live="off"`, and a polite status announces new errors at most every 5 seconds (`announce="lines"` counts lines, `"off"` stays quiet). Agents read the shown lines as its items and call `filter`, `search`, `nextError`, `previousError`, `copy`, `jumpToEnd` and `setWrap`; one with nowhere to go, or a change the app cancels, fails with the reason. Measured in Chrome (`node tooling/log-bench.mjs`, in `test:browser` with `--ci`): a 10,000-line burst paints about 45 ms after the append at 1×, half of it making the lines, and key to next paint while 2,000 lines a second stream in has a p95 of about 14 ms at 1×. The perf budgets hold its key presses (`log-viewer` in `perf:ci`) and gzip size.
- `ansi`: `parseAnsi` and `stripAnsi` read terminal output in one linear pass: SGR codes (16, 256 and truecolor colours, bold, dim, italic, underline, inverse, strikethrough, reset) become styled runs; other escape sequences, OSC strings (titles, hyperlinks), control characters and bidi overrides are dropped; a carriage return redraws the line. The text is always strings, never markup. `ansiCssColor` keeps a colour's hue and clamps its lightness to the theme's new `--ansi-lightness-min` and `--ansi-lightness-max`, so terminal colours hold 4.5:1 on `muted` in light and dark.
- `server-data`: `patch(changes, { inFlight: "cancel" })` (and `patchSource`) writes the answer and cancels the read in flight of each query it writes, instead of starting it again: the query keeps the patch and stops fetching, the read's late answer is dropped and nothing shows an error, as after a mutation's `settle` but without a mutation, so `mutationFn: (answer) => Promise.resolve(answer)` is no longer needed. A first read the patch writes nothing into still restarts, since its query would stay pending. `"restart"` stays the default.
- `server-data`: `patch(changes, { awaitRestarted: true })` resolves once every read the patch restarted has settled, following each query through later restarts (another patch, an invalidation) to its latest read, and never starts a read of its own; with `throwOnError` it rejects with the first failure, after retries, with the query function's own error. A caller can now tell a restarted read failed without `refetch: true`, which adds a read, and without awaiting the query's `promise`, which rejects with a silent `CancelledError` when another write restarts the read. `throwOnError` now applies to every read the call awaits. Tests count every query function call (a consumer whose every read overwrites per-item ETags can't afford an extra one) across a second write during the awaited read, a failure reported once, a read that retries, an invalidation, a first read, a cached query nothing observes, a removed query, `select` and typed errors.
- `model-scan`: `masks`, the engine's person masks as its coming `mask` event sends them (`{ source?: "face" | "body", width, height, data: Uint8Array }`, 0–255 confidence, row-major from the top left, the photo's aspect). The body mask, or one of the photo's aspect, dims the background around the person while detecting and picks the pixels that fly onto the model. Without one, a hull around the body's 33 pose landmarks (capsules around the limbs, the torso, a disc for the head) stands in, and without those every pixel flies. The root's points layer says which in `data-person` (`mask`, `landmarks`, `none`).
- `model-scan`: a point group takes `edges`, pairs of point indices joined by lines, so a skeleton or a face draws as a mesh; a `body` group of the 33 pose landmarks has the pose skeleton below the face by default (`poseEdges`). A group with edges draws only the points they join.
- `model-scan`: floating glass controls over the stage, from the registry's Button, SegmentedControl, Toggle, Toolbar and tooltips: over the photo a style picker (`styles` of `{ value, label }`, `selectedStyle`, `onStyleChange`; `style` stays React's inline style) and Make 3D (`onStart`); while working a progress ring, the stage's label, "Step n of 4", the percent and Cancel; over the finished model the style picker and a toolbar of views, the clip, Download (`onDownload`) and Start over (`onStartOver`), icon buttons with their names in tooltips; at `error` a card with the message, Try again and Start over over the dimmed stage. `controls="below"` puts the same controls under the stage. Every control shows only with its callback, every word is in `labels` (`start`, `step`, `startOver`, `download`, `play`, `styles`, `toolbar` are new), and on a coarse pointer every control reaches 44px without overlapping its neighbours. After the control that had focus goes with the stage, focus moves to the stage's main control (Make 3D, Cancel, Try again).
- `model-scan`: agents get `start`, `restart` (Start over) and `download` beside `cancel` and `retry`, with `action-refusal` semantics: a call the stage doesn't offer fails the step with why (`download isn't available while the scan runs.`), one with no callback says the app doesn't offer it, and one the app refuses through `details.cancel()` says so; a person's press gets `false`. `test/agent-refusals.test.tsx` covers each.
- `model-viewer`: `controls="gestures"` keeps drag, wheel, pinch and keys on the stage without the control bar, for controls of your own: `handleRef` hands over the viewer's handle, and `useModelViewerControls(handle)` its status, view, clips, clip and whether it plays, rendering only when one of those changes. `ModelScan` uses them so it shows one toolbar.
- `model-viewer`: `floor` draws a grid disc and a contact shadow under the model's feet, one draw call, in the theme's muted foreground, and pools the card colour over the stage. Scene content reads it from `ModelViewerSceneContext` (`floor.set({ opacity, pulse })`); `ModelScan` fades it in and runs a pulse across it as the model lands, and turns it on by default (`viewer={{ floor: false }}` turns it off).
- `tooling/model-scan-capture.mjs`: by hand, on the machine's GPU, captures every ModelScan stage per theme and width, a strip of the transition, and its frame times at any CPU slowdown (`--cpu=1,4,6`), from the hand-off to 3D to the end of the motion.

## 0.2.8 (2026-11-20)

### Added

- `server-data`: `useSourceMutation({ refreshOnError: false })` adds no read after a failed mutation, for a command whose failure changed nothing on the server; `optimistic` rows still roll back. The default still reloads the key.
- `useServerQuery(key, fetch, { select })`: TanStack's `select`, memoised and structurally shared, with `data` typed as the selection. The cache, `settle` and `seeds` keep the whole answer.
- `useServerQuery(key, fetch, { seeds: (data) => [...] })` and `defineResource({ key, fetch, staleTime, seeds })` with `useServerResource(resource, params, options)`: declare a resource once for every screen that reads it, and fill other resources from its answer with `other.seed(params, value)` (typed against that resource). Seeds are written once the fetch resolves, whether or not the seeded resource is mounted, never after an aborted fetch, and never over data that resource got after the fetch started. It replaces calling `setQueryData` inside a fetch behind `!signal.aborted`.
- Typed errors: `error` is the `defaultError` an app registers with TanStack Query's `Register`, or a type parameter after the data (`useServerQuery<Task, ApiError>`, `useServerPage<T, F, E>`, `useServerInfinite<T, F, E>`, `useServerTotal<T, F, E>`, `useSourceMutation<T, V, R, D, E>`, whose `onError` gets it). Without either it stays `unknown`, not TanStack's `Error`, since a fetch can reject with anything. `DefaultServerError` (from `server-data`) is that type.
- `createDataClient({ retry: false })` never retries, as `0` does.
- `networkMode` (`"online"`, `"always"`, `"offlineFirst"`) on `createDataClient`, for queries and mutations, and on every hook that reads or writes: `useServerQuery`, `defineResource` and `useServerResource`, `useServerPage`, `useServerInfinite`, `useServerTotal` and `useSourceMutation`. TanStack's default, `"online"`, pauses reads after the browser fires `offline`, so a page stays pending and never reaches its error state; an app whose backend is local (Electron IPC, localhost) or that shows its own offline UI should use `"always"`.
- `useSourceMutation({ scope: { id }, mutationKey })`: TanStack's `scope` runs mutations with the same id one at a time in call order, across hooks, each after the one before has settled (its refresh included); different scopes run side by side. The guide shows how to stop at the first failure with a flag set in `onError` and read in `mutationFn`. `mutationKey` finds them with `useMutationState` or `client.isMutating`.
- `server-data`: `usePatchSource(source)` returns `patch({ items, resource }, { refetch, throwOnError })`, for a change the app learned of outside a mutation (a push event, a socket message, another request's answer), and `patchSource(client, source, changes, options)` does the same outside React. `items(rows)` maps the rows of every page and infinite query under the key (totals stay) and `resource(current, queryKey)` every other query (`undefined` leaves one alone), mounted or not, without a request. A read in flight that left before the change could answer with the data from before it, so each one whose query the patch writes, and each first read (no data yet, so nothing to patch), is cancelled silently and started again in the same batch, with or without `refetch`: the number of requests stays the same, nothing is left pending, and the old answer or `AbortError` is dropped. A first read isn't left cancelled with `refetch: false`, since its query would stay pending with nothing to show. `refetch: true` also reloads the key, as `useInvalidateSource`, and resolves once the shown queries have reloaded. Tests cover `useServerQuery`, `useServerPage` and `useServerInfinite` with the old request resolving or rejecting after the patch.
- `refetchOnWindowFocus`, `refetchOnReconnect` and `refetchOnMount` (`true` when stale, `"always"`, `false`) on `useServerQuery`, `defineResource` and `useServerResource` (the call's option wins over the definition's), `useServerPage` (its total follows it), `useServerInfinite` and `useServerTotal`, and as app defaults on `createDataClient` (`refetchOnWindowFocus` now takes `"always"` too). Unset, they keep TanStack's defaults under `createDataClient`'s: no reload on focus, a stale query reloads on mount, and on reconnect unless `networkMode` is `"always"`. The guide and the skill say never to reload a resource whose reads overwrite per-item ETags a later write sends back, and to turn focus and reconnect off on its `defineResource`, since any reader that asks reloads the query for all.
- `action-refusal`: `parseActionRefusal(failure)` reads an `ActionRefusedError` back from an agent step's `error`, its `message` or the error itself, as `{ action, kind, text }`, and returns `null` for any other failure. UI SDK's `act` result keeps only the message of a failed step (`error: { step, message }`, from `messageOf(error)`, with no code, cause or data, locally and over WebMCP), so tests couldn't tell a refusal from another error. `ActionRefusedError` adds `text`, the sentence without the tag. `test/agent-refusals.test.tsx` checks it through `agent.act()`, and `tooling/agent-bridge-check.mjs` over WebMCP and the stand-in.
- The Agents guide and the skill's `references/agents.md` say that `document.modelContext` needs Chromium 158 or later, that the first Electron on it is Electron 46 (Chromium 160, stable on 5 January 2027 by Electron's schedule, tentative, checked on 20 November 2026), and that Electron 45 (Chromium 156) and older use the stand-in.
- `model-viewer`: a GLB that stores its morph targets scaled to fill their quantized range names the multipliers in a mesh's `extras.targetScales`, one per target; `weights` and `expressions` are now multiplied by them before they reach the mesh, so they stay in the targets' own units. `scaledWeights` (on `ModelViewer` and `ModelScan`) takes `weights` already multiplied, as an engine that writes such a GLB may send them; expressions are multiplied either way. A mesh that shares another's influences (an outline hull) is written once, with the scale of the one that has it.
- `model-viewer`: `onModelLoad(scene, animations)` runs once per loaded model before its first frame, to restyle its materials (a GLB's material `extras` are in `material.userData`), add outlines or hide parts; it may return a promise (the model shows once it resolves, so styling code that imports three.js can load with `import()`), and what it returns or resolves to runs when the model is disposed. A throw fails the load. ModelViewer reads no engine's material extras itself, and `material="toon"` stays a simple built-in.
- The ModelViewer and ModelScan docs, the showcase and `model-check` use real demo assets: a synthetic person (no real person) scanned by the open-source eskais-character engine, CC0, in `test/fixtures/model/character` with its licence. The viewer shows the character in two styles (soft toon and cel with an outline, two GLBs of about 989 KB, 530 KB gzip, loaded by URL) restyled through `onModelLoad`, with idle and wave clips and ARKit expressions. The scan replays the engine's recorded events (`scan-replay.json`, fetched on the first run) by their timestamps, 15 times slower than the engine ran them, through a `toModelScanProps` mapping: the body photo, its pose landmarks and the face mesh's contours placed onto it, the base model, the streamed weights and the finished character waving. `model-check` adds checks that both clips play and that an expression reaches the mesh multiplied by its `extras.targetScales`, and screenshots of both styles. The small generated figure stays for the unit tests and the error runs.

### Changed

- The task detail dialog is `xl` and sets a side column (meta, work, usage, links, location) beside the goal, acceptance and activity once it is 56rem wide; acceptance evidence folds into a disclosure and each attempt's usage toggle sits in its title row.
- A board column's collapse toggle moved to the end of its header with a fold icon and a tooltip, shown on hover or focus (always on touch and while collapsed).
- A thread with an `href` or `onOpenThread` opens from an "Open thread" button (`labels.openThread`) with its id in the tooltip; the bare id is never shown as text.
- `TaskStatusIcon` colours follow the column tones, so a proposal's icon is neutral, not warning.
- Dialogs and drawers fill with `--dialog-opacity`, so the task detail passes contrast under light glass.
- Fields share one surface style (`fieldSurfaceClassName`), and a `Field` holding a checkbox lays out as a row.

- Reduced motion stops infinite animations instead of making them flicker.
- `registry/lib/agent-task-board.ts` is now `agent-task-board-model.ts`, so it doesn't share a basename with `registry/ui/agent-task-board.tsx`. It also exports `activeAttempt` and `attemptCount`.
- Board labels gain `card`, `panel`, `table` and `filters.clearSearch`.
- The `theme` item ships the `dark` variant: `dark:` follows `.dark` and, before any script runs, the system scheme unless `<html>` opts into light. It stays below the one-line variant `shadcn` writes, which Tailwind then ignores.
- Installing `theme` into a stylesheet that `shadcn init` already wrote leaves no `--x: var(--x)` self-references in `@theme inline`: seeds, shapes, shadows and computed colours ship as `css` rules on `:root` and `.dark`. The radius scale runs to `4xl` and replaces the one `shadcn init` writes, and the base rules use the same `@apply` lists, so they merge instead of repeating.
- `theme` depends on `utils`: the theme's utilities (`text-meta`, `gap-items`, `rounded-surface`…) only merge correctly with its `cn`, which now also replaces `rounded-control`/`-choice`/`-surface`/`-floating` and `shadow-surface`/`-floating` with another radius or shadow.
- `text-caption`, `text-body-sm` and `text-body` no longer set a font weight, so `<strong>`, `<b>` and `<th>` keep theirs; meta, title and display steps still set one. `StageFilter` counts set `font-normal` to keep their look.
- `--link` and `--link-soft` derive from a new `--link-brand` seed (a blue, `oklch(0.55 0.2 260)`, by default) instead of `--brand`, so links keep a hue under the neutral palette. The colour palettes set it to their brand; the showcase theme editor edits it and adds it to the CSS snippet.
- The install docs list the `components.json` aliases shadcn needs to place registry files and rewrite their imports (`components`, `ui`, `utils`, `lib`, resolving through `paths` in the root `tsconfig.json`), and `consumer-check` installs through `~/` aliases.
- AGENTS.md and the skill say `--accent` is a surface only, never text or a stroke (use `border-input-strong`, `border-primary`, `ring-ring` or `text-link`); a unit test greps the registry for it.

### Fixed

- The skill's ⌘K recipe renders the `CommandDialog` beside the `Topbar`, with only its triggers in `center` and `centerCompact`: `center` is hidden on narrow screens, and a dialog inside it opened with no box. `tooling/shell-check.mjs` (part of `test:browser`) opens it at phone width.
- On narrow screens a `SidebarTrigger` opens its `Sidebar`'s drawer through the shared controller instead of rendering nothing, and a `Sidebar` with `trigger={false}` drops its in-place drawer button (`narrowTrigger` sets that alone). `<Topbar leading={<SidebarTrigger controller={…} />}>` is now one pattern for desktop and phone.
- A scrollable `TabsList` scrolls the selected or focused tab into view clear of the edge fades (by keyboard, pointer, an agent or on load, also inside `PageHeader`'s `tabs`), in either direction and without animating under reduced motion. It scrolls only the list, never the page.
- `CardHeader` (and `Section`) with an action is a wrapping row: the heading grows from an 11rem basis (`--card-heading-basis`), so a wide action wraps below the title as soon as the title would get narrower than that, instead of squeezing it to 8rem at a fixed 17rem container breakpoint. The heading parts sit in a `card-heading` wrapper; a `CardAction` must be a direct child.
- `Dialog`, `Drawer` and `ConfirmDialog` give focus back on close only from inside themselves, or from `<body>` while no other modal is open. A dialog that left the page while another modal opened (one whose focus moves in a frame later, like many third-party modals) pulled focus back to its opener behind that modal, which then closed. `useFocusReturn(finalFocus, ref)` takes the content's ref and returns `attach` for it.
- `MobileNav`: `--mobile-nav-offset` includes the bar's 1px top border, so a page's last line no longer hides under it. Labels never truncate: in a slot under 4.5rem they step down to the meta size, and they wrap to two short lines when they still don't fit ("Wellness" fits at 320px with five routes). The docs spell out the slots: up to five routes without `overflow`, four and More with it. `items` and `overflow` take readonly arrays.
- A `Form`'s `labelPlacement` reaches plain `Field`s inside it too, not only `FormField`s, unless the Field sets its own or holds a control that can't float its label. `FieldLabelPlacementDefault` (from `field`) provides that default.
- Readonly arrays are accepted wherever the registry takes options or items: `Select` `options` (and their groups) and `items`, `NativeSelect` `options`, `Combobox` `items` (now a thin wrapper over UI SDK's, whose type is mutable), `SiteHeader` `items`, `DataTable` `selection`, `DependencyChips` `items`, `AttemptTimeline` `attempts`, `StepForm`/`StepDialog` `steps` and `fields`, `UsageTable` `columns`, and `AgentTaskBoard` `tasks`, `columns` and `stages`. A type test covers each.
