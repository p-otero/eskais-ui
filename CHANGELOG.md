# Changelog

Versions follow [semver](https://semver.org). Before 1.0, a minor version can break compatibility. Release with `bun pm version <patch|minor|major>`, which bumps `package.json` and tags `vX.Y.Z`.

## Unreleased

### Added

- `locale` (lib): `useLocale(locale)` returns an explicit locale or the page's `<html lang>`, following it as it changes, and skips it on the server and the first render so hydration matches. `StatDelta`, `StatValue`, `QuantityValue`, `RelativeTime`, chart tooltips and data tables, attachment sizes, the inbox and the agent task board format with it, so a page in English no longer shows "12 %" on a machine set to Spanish. Each still takes `locale`; `Meter` and `Progress` already read the page's language through UI SDK.
- `settings-page` (block): `SettingsPage` lists its `SettingsSection`s in a navigation that sticks beside them on wide containers (48rem and up) and becomes a section picker (`Select`) that sticks on narrow ones, marking the section being read with an IntersectionObserver band below the sticky bars (`--settings-top`). Going to a section scrolls to it by id and focuses its heading without touching `location.hash`, so hash routers keep their route; `url={createUrlParam("section")}` records it and deep links and Back scroll to it, and `currentSection`/`onSectionChange` follow your own state. `SettingsRow label description` lays a control beside its label (a `Field`, so the label names it) and stacks when narrow; `SettingsFacts` is an inline `DescriptionList` for read-only facts; `SettingsDangerZone` edges its box in the destructive tone and `SettingsDangerAction` confirms through `ConfirmDialog` with `data-agent-confirm`.
- `dashboard-grid` (block): `DashboardGrid` lays a `stats` row (`DashboardStats` of `DashboardStat`, which draw a placeholder of the value's height while `loading`) over a grid of cards sized by its container: one column, two from 42rem, `columns` (3 by default) from 64rem, `gap-section` between cards. Rows are at least `--dashboard-row-height` (20rem) tall and the cards in a row share their height, so cards beside each other line up and none changes size between loading and loaded; a card whose content is taller grows its row rather than clipping it. `DashboardCard title description actions span rowSpan` is a region named by its title; with `status`, `data`, `error` and `onRetry` it loads through `DataState` (a skeleton, the error with Retry, `labels.emptyTitle` or `empty`). `DashboardChart` fills a card and takes its title as its name, `DashboardMeter label value hint` centres a ring meter in one, and `DashboardStat delta` takes a `StatDelta`. Labels are set once on the grid and overridden per card.
- `master-detail` (block): a list with a detail pane, used by any review queue, inspector or device list. `MasterDetail label renderList renderDetail emptyDetail header toolbar` lays the panes side by side and stacks them below 42rem of container width (a container query, so it works inside an app shell's main column): only the list, or only the open item with a Back button, never an overlay. The selection is controlled or uncontrolled (`selectedId`, `defaultSelectedId`, `onSelectedIdChange` with `cancel()`), and `url` keeps it in the URL through a `{ read, write, subscribe }` adapter: `createUrlParam(name, { in: "search" | "hash", history })` from the new `@/lib/url-param` works with plain, history and hash routers. Enter or a click opens a row; `followFocus` makes j/k move the open item; opening focuses the detail's heading and Close, Back or Escape (stacked) return focus to the row. `collapsible` folds the detail to a rail with an Expand button, `resizable` adds a named handle, and `storageKey` remembers both. Agents `open(id)` and `close()` it by its label. Every label is overridable.
- `List` virtualizes `ListItem` children. A row list whose children are all elements with a string `id` (a `ListItem`, or a row of your own that takes `id`) reads them as its data, as it does `items` with `renderItem`: past 200 rows (`virtualize="auto"`) only the rows in view render, j/k, Home/End and PageUp/PageDown reach every row and focus it, agents `select` rows that aren't rendered, and find in page reaches them; `title` is a row's text. Grouped lists, cards and other children render as before. Tests cover both paths with 5,000 rows.

- `StatDelta` (in `stat`): a change beside a Stat's value. `value` (a ratio by default, so 0.12 reads "12%"; `format` and `locale` change it) gives the direction by its sign, or pass `direction`; the direction gives the tone (up success, down destructive, flat neutral), `invert` swaps it for a metric where down is good, and `tone` overrides it. An arrow (lucide, mirrored in right to left) and the size sit in a soft tone chip, then your `comparison` ("vs. last week"). Screen readers hear `labels.up/down/flat(formatted)` ("up 12% vs. last week"), never the arrow or the colour.
- Ring meter: `Meter variant="ring"` with a `MeterRing size` child (`sm`, `md`, `lg`) draws the reading as a ring gauge with the value in the centre and the label below. It is UI SDK's `MeterTrack`, so the root keeps `role="meter"` and its value for screen readers; the drawing is `aria-hidden`, `tone` colours the arc, it fills the other way round in right to left, and it doesn't animate under reduced motion. `node tooling/shell-check.mjs` measures it (`?demo=gauge-check`).

- `description-list`: `DescriptionList` (a `dl`), `DescriptionItem` (the `div` HTML allows around a pair), `DescriptionTerm` and `DescriptionDetails`. `layout="stacked"` (default), `"inline"` (term beside details at `--description-term-width`, divided by rules, stacked again once the list itself is under 24rem, a container query) or `"grid"` (as many columns as fit at `--description-column-min`, at most `columns`). Spacing from the role tokens, so compact tightens it. An empty value shows a dash that reads `labels.empty` ("Not set"). `mono` for ids and hashes; `copyable` (with `copyValue`, `onCopy`) adds a copy button in the CodeBlock pattern: the value is a group named by its term with a `copy` action for agents, the button is hidden from them, and "Copied" is announced. `node tooling/shell-check.mjs` measures each layout wide and narrow.
- `shell` block: `Shell` turns one list of routes into an application's frame: a `SkipLink` to `<main id="main" tabIndex={-1}>`, a `Topbar` with the `SidebarTrigger`, a `brand`, the search triggers (`CommandDialogTrigger` with `mod+k`, `CommandDialogOpenButton` in `centerCompact`) and `actions`; a grouped `Sidebar` that sticks under the topbar, collapses (remembered under `storageKey`) and is a drawer on narrow screens; a `CommandDialog` with a Go to group of every route (`keywords`, the group's label) plus your `commandGroups` run by `onCommand`; and a `MobileNav` of up to four `mobile: true` routes and More, sticky at the end of the shell so the page always ends above it. `currentHref` (an href, or a matcher where the longest match wins) sets `aria-current="page"` in all three. Router-agnostic: `onNavigate(href, route)` for a history router, `#/route` hrefs for a hash router, or plain links that fast links follow; sidebar routes are always Links with `onFollow`, so agents follow them by name. Every string is a `labels` entry. A navigation re-renders only the two routes whose current state changed. `--shell-height` sizes it inside a pane.
- `SidebarGroup`: `label` is optional (a group without a heading), and `tone="muted"` quiets a group's items, like sections on their way out; the current page keeps its fill.

- `document-workspace` (block): a notes or docs workspace. Slots for an explorer, tabs, breadcrumb, toolbar, the document, a status bar, an aside (backlinks, properties, outline), an alert and quick open; `mode`/`onModeChange` (`edit`, `read`), `explorerOpen`, `asideOpen`, `saveState` (`saved`, `saving`, `unsaved`, `error`), `labels` and `storageKey` (the columns' state and widths). It lays out by its container (`narrow`, 760 px), so it fits an app shell's `<main>`: resizable, collapsible columns when wide, drawers when narrow. `DocumentQuickOpen` (a `CommandDialog`, Ctrl/Cmd+P through the shared shortcuts) and `DocumentOutline` (the caret in edit mode, focus in read mode). Switching modes keeps the reading position by heading; drawers, quick open and menus return focus to the document. Named landmarks and toggles that agents press by name. The docs page has a live demo with three notes, wikilinks, an embed, frontmatter, backlinks and a save-state simulator; `node tooling/document-workspace-check.mjs` drives it in Chrome (test:browser, test:compiler).
- `markdown-editor`: a `ref` gets a `MarkdownEditorHandle` once the editor mounts, so a host's Insert or Link menu and an outline drive it without importing CodeMirror: `focus`, `getValue`, `getSelection` and `setSelection(anchor, head?)` in offsets of the Markdown string (CRLF counted as written), `insertText`, `insertWikilink(target, alias?)`, `insertLink(href, text?)`, `wrapSelection(before, after?)`, `runCommand(name)` for the toolbar's formats and levels, `scrollToLine(line)` and `getScrollLine()`. `onWikilinkClick(target, event)` on Ctrl/Cmd+click or Enter in a wikilink or an embed. `embedPreview` (off by default) shows `![[target]]` off the caret as `renderEmbed(target, alias)` or a placeholder.
- `markdown-view`: `![[target]]` and `![[target|alias]]` embeds through `renderEmbed` (a link-like placeholder by default); `onWikilinkClick(target, event)` for wikilinks, which render through `Link` (fast links, hash routes, agents' `follow`) or as a button when they have no address; `frontmatter` (`"hide"` by default, `"properties"`, `"raw"`) and `renderFrontmatter` for a leading YAML block, read by `parseFrontmatter` with no YAML dependency; `extractHeadings(markdown)` for an outline.

- `page-source`: one backend-agnostic contract for paged data (`PageSource`, `PageRequest`, `PageResult`, capabilities for page or cursor positions and exact, estimated or no totals) and an adapter for each wire format, none of them tied to a backend library: `pagedSource` (0- or 1-based), `offsetSource`, `cursorSource` (opaque or keyset cursors), `relaySource`, `linkHeaderSource` (an RFC 8288 `Link` parser), `springPageSource` and `springSliceSource`, plus `arraySource` for demos and tests (latency, failures, abort). `createPageController` derives the request, goes back to the first page when the filter, sort or size changes, picks the navigation from what the source gives, debounces search, keeps the URL in sync and writes "Showing 21–40 of 312" for a live region. `readJson` throws an `HttpError` with the status.
- `filter-schema`: `defineFilters` declares typed filters (text, options, boolean, number, date, date range, remote options) that are also the field whitelist; `FilterValues` infers their values and `toFilterAst` builds one canonical filter. Serializers for flat query params (three naming styles), a JSON body, RSQL, OData, Spring Filter, Hasura or Prisma `where` and `q`-only search escape for their grammar and refuse what they can't write safely. `createUrlCodec` keeps schema values in readable, round-tripping params.
- `server-data`: `useServerPage`, `useServerTotal`, `useServerInfinite`, `useInvalidateSource`, `useSourceMutation` (invalidates by default, optimistic on request) and `usePageController` on TanStack Query 5, which never shows in their types. The previous page stays while the next loads, superseded requests are aborted, a 4xx is never retried. They use the app's `QueryClient`, or a shared default; `DataProvider` and `createDataClient` provide the defaults (two retries except on a 4xx, 30 s fresh, no refetch on focus).
- `DataTable manual`: the server sorts and pages. `rows` is the current page as given, sort and page changes are only reported, `total` or `pageCount` sets the pages, and columns sort by `sortField`. `busy` marks the table `aria-busy` while the rows stay, and `secondarySorts` shows each later sort's place on its header (`labels.sortRank`). Client mode is unchanged.
- `url-state`: `historyUrlState`, `hashUrlState` (the query inside `#/route?…`) and `memoryUrlState` behind one `UrlStateAdapter` shape, and `useUrlState`.
- `token-input`: UI SDK's Token Input styled as a field (`bg-field`, `border-input`, the control shape, growing with its chips), with `TokenInput`, `TokenInputEditor`, `TokenInputToken` (`tone`, soft tone tokens) and `TokenInputTokenRemove` (lucide `XIcon`, named by `labels.remove`, "Remove {label}", with a touch target). `tokenType="label"` makes it a list of labels with a `string[]` value (readonly arrays welcome): Enter or a comma turns the typed text into a label, a paste splits on commas and line breaks, `validate` and `max` keep a label as text to fix, and repeats are dropped. Backspace, the arrow keys, undo and redo come from UI SDK. It works in `Field` and `FormField`, floats its label with `labelPlacement` `in` and `on`, and agents set it by label (`setValue("bug, docs")`, `insert`, `removeToken`, `clear`). Without `tokenType` it holds UI SDK's mix of text and tokens, for mentions and files. FormField's adapter table moved to `field` (still exported from `form`), so a control's module can add itself; `FormControlAdapter` gains `blur`. The theme's `field-floated` variant floats a label over a token input that holds something.
- `carousel`: `CarouselStatus` shows the current page and the page count ("1 of 3", `labels.status` translates it) and announces it politely only when the page changes, never on load or while rotating. `useCarouselState()` returns UI SDK's own `page`, `pageCount` (null until the slides are measured), `playing` and `orientation` to any part inside a `Carousel`, so a header can show its position without duplicating state; `Carousel` children can also be a function of that state.
- `useSidebarState({ storageKey })` (`sidebar`): one controller and collapsed state for a `Sidebar` and its `SidebarTrigger`, remembered in localStorage (`sidebarProps`, `triggerProps`). `Sidebar collapse="hide"` slides the sidebar away when collapsed instead of leaving an icon rail, for items without icons.
- `--topbar-height` (theme): a `Topbar`'s height, which it now keeps as a minimum, for anything that sticks under it.
- `MeterValue` and `ProgressValue` take `formatValue(value, { min, max, percent, text })`, which replaces the visible value with any node while screen readers keep the root's text. The root's `format` (`Intl.NumberFormat` options or a function) still changes both. The default stays locale-correct: es-ES writes "21 %" with a no-break space (U+00A0), as CLDR does, and the docs now say so.
- Agent skills as registry items: `npx shadcn@latest add @eskais/eskais-ui-skill @eskais/eskais-perf-skill @eskais/eskais-mockup-skill` writes them into `.agents/skills/<skill>/` (`registry:file` items with a `~/` target). `eskais-perf` is new: virtualized rows, effects in hooks, React Compiler-friendly code, transform and opacity motion, fast links for navigation only, blur off large animated surfaces, and measuring with the React Profiler and the Performance panel. A `/docs/agent-skills` guide lists them and how Codex, Cursor and Claude Code find them.
- `/docs/mockups` covers the five levels (project components, `@registry/<name>` items cached in `.mockups/.registry/<ref>`, `parts/`, UI SDK primitives with an `sdk-reason`, recorded gaps), `inspect --registry` and `--sdk`, the `validate` summary, a quickstart from an empty folder, a "For agents" section and how to run the CLI by path or with `bun link`. Mockups and Agent skills sit under Tools in the docs nav.

### Changed

- Headings and regions that take focus from script, not from the keyboard (an opened master-detail item or settings section, a step's title, the task detail's title, a form's root error, `PageLayout`'s and `Shell`'s `<main>`), use `focus:outline-none` and draw no ring, even when Chrome treats the focus as visible. The theme does the same for any `[tabindex="-1"]` element, such as a `SkipLink` target.
- `DocsLayout` is an app shell. `topbar` puts a `Topbar` across the top; the sidebar sticks under it at the full remaining height and scrolls on its own (no more fixed box cut off by a floating header, and no white panel that ends early), collapses through the topbar's `SidebarTrigger` and is a drawer on narrow screens. `header` (the breadcrumb) now sits above the page in the main column instead of in a sticky full-width bar, the table of contents sticks under the topbar, and everything in the page scrolls into view below it. `--docs-height` sizes it inside a pane. Without `topbar`, `--docs-top` still clears a header of your own.
- Docs site: docs pages use that shell, with a full-width `Topbar` (sidebar trigger, brand, navigation, search, theme and GitHub); the landing page keeps the floating header.
- The `eskais-ui` skill is written for a project that installs the components: `SKILL.md` keeps the install steps, a list of which component to use and the rules, and the details moved to `references/` (forms, lists and navigation, styling, toasts and testing, AgentTaskBoard). How to add a component to the registry moved to `AGENTS.md`.

### Fixed

- `markdown-editor`: Heading, Quote and the list commands (toolbar, text style menu, slash menu) left the caret before the marker they added on an empty line or at a line's start, so typing gave `Hola# `. The commands now map the selection through their change and put it after the marker, for every line of a multi-line selection too.
- `markdown-editor`: the slash menu closed as soon as the query held a character its trigger's default pattern stops at (`?`, `)`, `'`, `/`, `[`, `€`), which read as closing when nothing matched. It now stays open with its empty state (`labels.noMatches`) until Escape or a space.
- `markdown-editor`: a leading YAML block was previewed as a rule and a setext heading; it now shows as written, in a muted monospace block, and round-trips byte for byte. `![[embeds]]` parsed as an image around a link.
- `markdown-editor` docs name the `dropdown-menu` it installs and the parts its toolbar imports, for apps with a `dropdown-menu.tsx` of their own.
- `DataState` fills the space it is given (`w-full`, and `flex-1` in a flex container) instead of shrinking to its content inside a flex row, so a list in it spans the whole box. The States demo shows a `List` of projects in a `Card`, at the same height for every status.
- Docs site theme editor: the site's stylesheet never scanned the showcase file the editor lives in, so the brand colour area and hue track had no size (nothing to drag, so the colours never changed), the swatches had no fill and the columns had no gaps or padding. The editor now lays out in two columns only when its container has room, its contrast rows wrap, and the CSS shows in a `CodeBlock`.
- `@eskais/mockup` `validate` type-checks a project whose root `tsconfig.json` only lists `references` (Vite's template) with the referenced config that sets `jsx`, instead of reporting every alias import as missing.

- Icon buttons show their name in a tooltip. `Button` and `Toggle` with `size="icon"`, and `DialogTrigger`, `DialogClose`, `DrawerTrigger`, `DrawerClose`, `PopoverTrigger`, `PopoverClose`, `DropdownMenuTrigger`, `ToastAction`, `ToastClose` and `FilterBarButton` with it, show their `aria-label` on hover and keyboard focus, with the `shortcut` keys after it (no longer inside the square button). The tooltip labels the control with the same text, so screen readers hear the name once, and it stays out of the agent snapshot. Never on touch, nor on a natively disabled or `aria-hidden` control. `tooltip={false}` turns it off; `tooltip="…"` or `{ content, side, align }` describes or places it, on any button. Tooltips group without a provider, so a toolbar shows the next one at once.
- The registry's other icon-only controls do the same: dialog, drawer, sidebar, lightbox and toast close buttons, the carousel, pagination, calendar and number input steps, the combobox, date picker and input clear and trigger buttons, the code block copy button, the sidebar collapse toggle, the markdown editor toolbar (with its shortcuts) and the board column toggle. `ControlTooltip` (in `tooltip`) is the helper, for controls of your own.
- `Toggle size="icon"` and the button-like triggers with `size="icon"` require `aria-label` at the type level, like `Button`.
- Lint: `eskais/icon-button-needs-label` flags an icon-only `Button` or `Toggle` without `size="icon"` and an `aria-label`. The `lint-rules` item ships it (`eskais-oxlint-plugin.js`, loaded by `eskais-ui.oxlintrc.json`).

- `Tabs` and `SegmentedControl` take `activateOnPress` (off by default): a primary mouse or pen press selects the tab or segment before release, like Linear and macOS. Touch still selects on release, so scrolling a tab bar doesn't select; keyboard and agents are unchanged. The press goes through the component's controller, so `onValueChange` (reason `item-press`), `cancel()`, controlled values, disabled items and read-only still apply, and a `controller` you pass keeps working. WCAG 2.5.2 allows it because the change is reversible; actions and menus always activate on release. `node tooling/press-check.mjs` (in `test:browser`) checks it in Chrome.

### Fixed

- Shortcuts Dialog: on its docs page `?` opened the dialog but, with focus outside the demo (as after any click on the page, and always in Safari, which doesn't focus a pressed button), it listed only its own row, and there was no way in without a keyboard. `ShortcutsDialogTrigger` (a `Button` look, inside `ShortcutsDialog`) opens it, takes focus first so its `ShortcutScope` is listed, and is what agents press; the demo has a Keyboard shortcuts button.
- `ShortcutsDialog` no longer throws when it opens from `open`/`onOpenChange` or a trigger: it lists the shortcuts while it renders, and `useShortcut` read its options through effect events, which React forbids during render.
- A symbol or digit shortcut (`?`, `/`, `1`) matches the character typed, whether the layout needed Shift, AltGr or Option for it. Only `?` with Shift was matched before, so `?` with AltGr or Option, `/` on a Spanish layout (Shift+7) and digits on AZERTY never fired. Letters keep their exact modifiers.
- Calendar ranges draw one continuous band: the middle days take a soft `accent` fill with no gaps or rounding, and the start and end keep their `primary` circle with the band running under their inner half. A one-day range is only its circle, the band breaks cleanly between weeks, mirrors in right to left and looks the same while a range is being picked. Every day's focus ring follows its circle and stays above its neighbours. Middle days used to keep `data-selected`'s `primary` fill, so they showed as separate dark squares. DatePicker and DateTimePicker share it. `node tooling/calendar-check.mjs` (in `test:browser`) measures the band.
- Focusing a field no longer zooms the page on iOS. A `text-entry` type step (`--type-entry-size`) is 14px as before on a fine pointer and 16px on a coarse one, and Input, InputGroup, Textarea, the Select trigger, NativeSelect, Combobox, CommandInput, NumberInput, DatePicker, DateTimePicker's time and MarkdownEditor use it. Pinch-zoom stays allowed. `node tooling/touch-check.mjs` (in `test:browser`) measures every text-entry control on an emulated phone.
- Parts built on a UI SDK part keep their registry `data-slot`. UI SDK keeps a part's own slot over a `data-slot` prop, so `ListItem`'s row button read `button` instead of `list-item-primary`, an option row of a selectable `List` lost `list-item` and its group `list-group`, and the same happened to `attachment-thumb`, `attachment-more`, `filter-bar-reset`, `data-table-sort`, `sidebar-trigger`, `attempt-thread`, `task-card-pull-request`, `code-tabs`, `lightbox`, `shortcuts-dialog`, `mobile-nav` and `date-time-picker-zone`. Each now sets its slot on the element it renders (`render`), and a test fails when a registry file passes `data-slot` straight to a UI SDK part or to `Button`. `Button` hides its idle spinner by its own class, so it stays hidden under any slot. `mobile-nav-link` still reads `navigation-menu-link`: a `render` there would turn off the fast link.
- `List` names the list itself. Its `aria-label` sat on a `div role="group"` around an unnamed `ul`, so `getByRole("list", { name })` found nothing and screen readers announced a group and then an unnamed list. The root is now the `ul` (`role="list"`, which Safari needs under Preflight) or, for a selectable list, the Listbox itself, each named by `aria-label`; the group is gone. Agents still find the list by that name with `select(id)`; a selectable list's listbox now shows beside it under the same name with `setValue`, and a step resolves by its action.
- `ChartDataTable` takes rows typed by an `interface`. It required `Record<string, unknown>` rows, so `interface Point { d: string; v: number }` failed with TS2322 (index signature missing). It is generic over `TRow extends object`, with `labelKey` and `keys` checked as `keyof TRow`. `ChartRow` is now `object`.
- `SidePanel` wraps its header actions below the title, as `CardHeader` does: the heading grows from `--card-heading-basis` (11rem), so a `StatusPill` and a small `Button` in a 24rem panel no longer squeeze the title and wrap the description one word per line. The close button keeps its corner. New slots: `side-panel-heading`, `side-panel-description`, `side-panel-actions`. `node tooling/shell-check.mjs` measures it at 24rem (`?demo=side-panel-check`).
- `SidePanel narrow` decides what happens on narrow screens. It always became `absolute inset-0`, hiding the page behind a panel open on load. `"stack"`, the new default, keeps it in the flow, full width, and wraps its flex parent so it goes below the list; it hides nothing and traps no focus. `"overlay"` is the old behaviour (the `inbox` block keeps it, its list being a tall scroller). `"sheet"` opens it as a modal bottom `Drawer`: focus moves in, its shortcuts still run, and Escape or the close button return focus to `returnFocus()`, resolved as it starts closing so a caller that clears its selection in `onOpenChange` still gets it. `use-media-query` (`useMediaQuery`, `narrowQuery`) joins the item. `node tooling/shell-check.mjs` checks each mode at 375px.
- Table cells no longer always truncate. `TableCell wrap` wraps long text onto more lines instead of cutting it at `max-w-80`, and `DataTableColumn` takes `wrap`, `cellClassName` and `headerClassName`. A cell that stays truncated now shows its whole text in a `title` while it overflows, set as the pointer arrives so cells that fit get none (a `title` you pass stays). `node tooling/shell-check.mjs` checks a wrapped column beside a truncated one (`?demo=table-check`).

### Fixed

- `lucide-react` is pinned to 1.68.0 (2026-11-04), the oldest release that exports every icon the registry uses, instead of 1.73.0 (2026-11-14): `shadcn add` failed with `ERR_PNPM_NO_MATURE_MATCHING_VERSION` for consumers with a 7-day pnpm `minimumReleaseAge`, since shadcn installs dependencies before it writes any file.
- Fast links work in hash routers: `@fast-link/core` 0.0.2 leaves every `#…` href native, so `Link`, `ButtonLink`, `NavigationMenuLink` and `FastLinkRegion` links to `#/route` only followed on release. An `href` that starts with `#/` now follows on press, through `onFollow` or by setting `location.hash`; other `#…` hrefs are in-page anchors and stay native. `data-fast-link-hash-prefix` on any ancestor, or `FastLinkRegion hashPrefix`, sets another prefix (`#!/`), and an empty one turns hash routes off.
- A `Field` inside a `Form` with `labelPlacement="in"` or `"on"` takes the Form's placement only in the floating layout: a `FieldLabel`, then a control that can float its label, then only a `FieldDescription` or `FieldError`, with no padding of its own. A Field styled as its own box (`className="border p-3"`, a help `<p>` after the control) drew its label over the control's value; it now keeps the label on top. A `FormField` with padding in its `className` does the same. A Field's or FormField's own `labelPlacement` still wins, `top` included.
- Item docs: `sidebar` said a `SidebarTrigger` renders nothing on narrow screens; it opens the Sidebar's drawer, and a Sidebar with `trigger={false}` renders no drawer button of its own. `virtual-rows` named `VirtualFindStubs`, which is `GapFindStubs`. A test fails when an item's docs or the skill name a component or hook that no registry file exports, or one marked deprecated.

### Changed

- `eskais/no-inline-icons` runs on `apps/**` too. The showcase and site draw their icons from `lucide-react` (the global search, the shell's navigation, the examples); the brand logos left disable it with a reason.
- Every npm dependency in `registry.json` is pinned to an exact release at least 7 days old. `tooling/check-dependency-age.mjs` checks the publish times in CI (it skips offline), with the exceptions it lists and why: UI SDK, whose first release is from 2026-11-12. The `release-age` consumer check installs `dialog` with pnpm under a 7-day `minimumReleaseAge`.

## 0.2.0 (2026-11-17)

### Added

- Fast links: `Link`, `ButtonLink` and `NavigationMenuLink` follow a same-origin link on a primary mouse press instead of on release, with `@fast-link/core` 0.0.2 (through `onFollow`, or `location.assign`). `fast={false}` opts a link out and `data-no-fast-link` on any ancestor a region or the app; `FastLinkRegion` and `useFastLink` cover plain anchors. A `render`ed router link or a link with its own `onClick` stays on click unless it has `onFollow`.
- Icons come from `lucide-react` (1.73.0): every hand-drawn icon in the registry is now a lucide import, and the items that use one depend on it. `icon` adds `Icon`, which names an icon for screen readers (`<Icon icon={TrashIcon} label="Deleted" />`). The `eskais/no-inline-icons` lint rule flags any other `<svg>` in `registry/**`.
- Deprecated: `ChevronIcon` from `select` and `PanelIcon` from `sidebar` (import `ChevronDownIcon` and `PanelLeftIcon` from `lucide-react`). `CloseIcon` is no longer exported from `task-detail-parts`. `select` still exports lucide's `CheckIcon`.
- `StepDialog` `resultStep={{ title, render: (result, { close, restart }) => … }}` (opt-in) shows what `onSubmit` resolved with inside the dialog instead of closing: focus moves to the result heading, Done (`labels.done`) and Escape close it, and `restart` starts over from step 1. `onOpenChange` now gets `details.reason` (`submit`, `done`, `cancel`, `escape`, `outside`, `dismiss`, `trigger`).
- `icon` item: `<Icon icon={TrashIcon} label="…" />` for meaningful icons; `eskais/no-inline-icons` rejects hand-drawn SVG icons in the registry.
- Keyboard-first lists: `shortcuts` (`useShortcut`, `ShortcutScope`, `ShortcutHint`, `Button`/`DropdownMenuItem` `shortcut`), `shortcuts-dialog` (`?`), `row-navigation` (j/k, Home/End, PageUp/PageDown, Enter, x) in List, DataTable and the AgentTaskBoard table and backlog, `virtual-rows` (TanStack Virtual past 200 rows), `SidePanel` and the `inbox` block.
- `@eskais/mockup` (`packages/mockup`, run from the repo with Bun): build a screen as TSX with the project's own components and fixtures into one offline HTML file, then `validate` it. A `/docs/mockups` guide covers it, with an A/B benchmark against hand-written HTML (`packages/mockup/BENCHMARKS.md`).
- `@eskais/mockup` levels: a screen uses the project's components first, then registry items it has not installed (`@registry/<name>`, cached under `.mockups/.registry`), then a composition in `parts/`, then UI SDK primitives with a stated reason, and records a gap instead of a raw control. `inspect` gains `--registry` and `--sdk`; `validate` checks them and prints an install, proposed, SDK parts and gaps summary.
- `bun run test:compiler`: the showcase built with React Compiler, with the browser checks run on it (in CI).

### Changed

- Lint: the shared `@p-otero/oxlint-rules` presets replace the local rules (`p-otero/spacing-tokens`, `p-otero/no-low-value-comments`); effects live in hooks (`use-*.ts`); the `lint-rules` item ships the `react` and `ui-tailwind` presets.
- Shell: the global search dialog sits beside `Topbar` (only triggers in `center`/`centerCompact`); `SidebarTrigger` opens the sidebar drawer on narrow screens; tabs scroll the active tab clear of the fade; `CardHeader` wraps its action below the title sooner; dialog focus return never steals focus from another modal; `MobileNav` labels shrink or wrap and its offset includes the border; plain `Field`s inherit `Form`'s `labelPlacement`; option and item arrays accept `readonly`.
- `DocsLayout`: on narrow screens the header row scrolls with the page instead of covering it.

### Fixed

- `useFormFieldArray` takes `keyName` like react-hook-form's `useFieldArray` (`useFormFieldArray("components", { keyName: "fieldKey" })`), typed by a third type parameter, so rows whose items carry their own `id` keep it. `createForm().useFormFieldArray` infers it too.
- `FormDialog` `reviewStep.prepare(values, { form })` gets the form instance. Values it returns are written into the form, so Edit shows them and they are submitted; values it writes through `form` without returning any are parsed again and reviewed. Returned values win.
- `formIssueMessage` writes a reserved `@@form:` prefix, so every code round-trips: `formIssueMessage("email")` used to come back as `invalid` with the text "email". A coded issue's `message` is now `undefined`, not the code, so a `messages` function that prefers `issue.message` no longer prints the raw code. Messages in the earlier `code|{json}` form still read.
- `select.tsx` writes its internal empty value with an escape sequence instead of a raw NUL character, which made git treat the file as binary. A test fails on any raw control character other than tab, LF and CR in `registry`, `apps`, `tooling` and `test`.
- README and skill: a flat layout (`#ui/*` and `#components/*` on one `src/components` folder) is supported, and shadcn then writes the imports between components as `#components/x.tsx`. The `imports-flat` consumer check covers it.

### Fixed

- The skill's ⌘K recipe renders the `CommandDialog` beside the `Topbar`, with only its triggers in `center` and `centerCompact`: `center` is hidden on narrow screens, and a dialog inside it opened with no box. `tooling/shell-check.mjs` (part of `test:browser`) opens it at phone width.

- `CardHeader` (and `Section`) with an action is a wrapping row: the heading grows from an 11rem basis (`--card-heading-basis`), so a wide action wraps below the title as soon as the title would get narrower than that, instead of squeezing it to 8rem at a fixed 17rem container breakpoint. The heading parts sit in a `card-heading` wrapper; a `CardAction` must be a direct child.
- `Dialog`, `Drawer` and `ConfirmDialog` give focus back on close only from inside themselves, or from `<body>` while no other modal is open. A dialog that left the page while another modal opened (one whose focus moves in a frame later, like many third-party modals) pulled focus back to its opener behind that modal, which then closed. `useFocusReturn(finalFocus, ref)` takes the content's ref and returns `attach` for it.
- `MobileNav`: `--mobile-nav-offset` includes the bar's 1px top border, so a page's last line no longer hides under it. The docs spell out the slots: up to five routes without `overflow`, four and More with it. `items` and `overflow` take readonly arrays.
- A `Form`'s `labelPlacement` reaches plain `Field`s inside it too, not only `FormField`s, unless the Field sets its own or holds a control that can't float its label. `FieldLabelPlacementDefault` (from `field`) provides that default.
- Readonly arrays are accepted wherever the registry takes options or items: `Select` `options` (and their groups) and `items`, `NativeSelect` `options`, `Combobox` `items` (now a thin wrapper over UI SDK's, whose type is mutable), `SiteHeader` `items`, `DataTable` `selection`, `DependencyChips` `items`, `AttemptTimeline` `attempts`, `StepForm`/`StepDialog` `steps` and `fields`, `UsageTable` `columns`, and `AgentTaskBoard` `tasks`, `columns` and `stages`.
