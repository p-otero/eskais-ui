# 3D: model viewer and model scan

`ModelViewer` (the `model-viewer` item) shows a glTF or GLB people can turn. `ModelScan` (`model-scan`) shows a photo turning into a 3D character while your engine works. Neither runs a model or fetches anything but the model URL you pass.

## Cost

The viewer's shell (stage, poster, controls, the primitive) is about 74 KB gzip, two thirds of it UI SDK shared with every item. three.js and react-three-fiber are a separate chunk of a few hundred KB, imported only when a stage nears the viewport (200 px before it), only with WebGL, and never on a page without a viewer. `preloadModelViewer()` starts it early, like on hover over a link to the page. A `ModelScan` starts it at `detecting`, so it's there by `building`.

## ModelViewer

```tsx
<ModelViewer
  model="/models/figure.glb" // a URL, its bytes (ArrayBuffer), or a loaded { scene, animations }
  alt="A stylised figure in a teal shirt" // required: the stage is an image to assistive tech
  poster="/models/figure.png" // until it loads, and without WebGL
  summary="A standing figure with short hair. Clips: Idle, Wave." // a visible text alternative
  aspectRatio={3 / 4}
  weights={{ Smile: 0.6 }} // morph targets by name, 0 to 1
/>
```

- **Camera.** Drag turns, wheel and pinch zoom; with the stage focused, arrows turn, + and - zoom, Home resets. `view` / `defaultView` / `onViewChange` take `front`, `three-quarter`, `side`, `back`, or `null` after a free turn. `framing="full"` fits the model; `framing={{ center: [x, y, z], radius }}` (the model's own units) frames a part, like the face.
- **Clips.** `clip` / `defaultClip` / `onClipChange` (the first clip by default), `playing` / `defaultPlaying` / `onPlayingChange` (left out or `null`: plays, except under reduced motion), `loop`, `speed`. A play toggle and a native select show when the model has clips.
- **Weights** ease in the render loop: a new `weights` object renders React once, never per frame. Stream them as often as your engine produces them.
- **Look.** `material="toon"` for a three-tone shade; `background="transparent"` to show what's behind; the stage takes `bg-muted` otherwise, so it follows the theme, dark mode and glass. `autoRotate` (true or degrees a second) turns it while nobody drags; never under reduced motion.
- **Rendering.** It draws only while the camera, a clip or a weight moves, and not at all off screen or in a hidden tab. Under reduced motion camera moves jump.
- **No WebGL, or a failed load:** the poster stays with a message (`labels.unsupported`, `error`), and the failure is announced at once.
- `controls={false}` hides the controls and makes the stage still and unfocusable; `load={false}` holds the scene back; `overlay` puts DOM over the canvas; `sceneChildren` puts your own three.js content inside it, reading `ModelViewerSceneContext` (the viewer's handle and the model's rig) from `model-viewer-rig`.

Agents find the viewer by `alt`, with the clips as items, and call `rotate(yaw, pitch?)`, `zoom(steps)`, `reset`, `setView(view)`, `play`, `pause` and `selectClip(name)`. Each throws with the reason before the model has loaded or for a clip it doesn't have.

## ModelScan

Drive it from your engine's events; keep this shape:

| Prop       | From the engine                                                       |
| ---------- | --------------------------------------------------------------------- |
| `stage`    | `photo` → `detecting` → `building` → `refining` → `ready`, or `error` |
| `points`   | `{ x, y }[]`, fractions of the photo, while detecting                 |
| `model`    | the base GLB (URL or bytes) with morph targets, from `building`       |
| `weights`  | `Record<string, number>`, streamed while refining                     |
| `progress` | 0 to 1 within the stage; leave it out while unknown                   |

```tsx
<ModelScan
  src={photo.url}
  alt="Your photo"
  width={photo.width}
  height={photo.height}
  stage={stage}
  points={points}
  model={model}
  weights={weights}
  progress={progress}
  error={error}
  modelAlt="Your 3D character"
  idleClip="Wave"
  onCancel={() => engine.cancel()}
  onRetry={() => engine.start()}
/>
```

- At `building` the photo moves into the 3D scene on a plane the front camera sees exactly where the 2D photo was, then burns into particles while the camera eases to the three-quarter view and the model fades in where it stood. Under reduced motion the photo crossfades into the model instead: no flight, no particles, and the progress bar under the stage shows throughout.
- At `ready` the idle clip plays (unless motion is reduced) and the viewer's controls appear. Pass more viewer props through `viewer` (`framing`, `material`, `summary`, `labels`).
- Cancel shows before `ready` when `onCancel` is set; Retry at `error` with `onRetry`. Agents call `cancel` and `retry`; outside their stage they throw.
- Each stage is announced (`labels.stage`), progress at most every tenth and two seconds, errors at once.
